# 常见质疑与回应

> 本文回答五个最可能被问到的方法论问题。所有数字都出自 `数据分析岗JD实证分析.html` 及其数据集 `jd_dataset_v3.csv`，可复现。  
> 写在前面的一条总原则：**判据没有正确答案，只有可接受的错误率。** 下面的每个回答都是同一个结构——承认误差 → 推演最坏情况 → 看结论是否还站着。

---

## 1. "你这标题党判定准吗？靠关键词能判对？"

**承认误差**：关键词表会两头漏——会漏（一条录入岗若一个词都不命中就混进来），也会误杀（优质岗可能被误踢）。所以 19 条标题党要读作"**至少** 19 条"，5.8% 是下限。

**推演最坏情况**：把最容易被质疑的两条改判（订单指令岗改回真岗、一条短而干的岗判为标题党），太原标题党率从 16/74 = **21.6%** 变为 14/74 = **18.9%**。

**结论是否还站着**：一线是 1/250 = 0.4%。改判前后，太原与一线的差距都是几十倍。**结论对判据的边界误差是稳健的。**

---

## 2. "删完标题党剩下 309 条，这个数可信吗？"

**承认误差**：309 不是"世上真有 309 条真岗"，而是**操作性定义**——按本项目的"挂羊头"判据筛出来 309 条。判据若有 6 条误差，真值可能是 303。

**推演最坏情况**：假设太原被判为真岗的岗里有 6 条其实是假岗、且都不提 Python（最不利于结论的假设），太原 Python 要求率变为 21/52 = 40.4%，置信区间 [27.0%, 53.7%]。

**结论是否还站着**：一线区间是 [57.1%, 69.0%]。两段区间**仍不重叠**——"太原明显低于一线"不受判据误差影响。这就是敏感性检验：故意把最坏情况推一遍，结论不倒，说明结论不依赖那个有争议的判据。

---

## 3. "为什么分城市算，不分城市算不是样本更大？"

**承认误差**：分城市后太原只有 58 条真实岗，百分比误差大（±12.4 个百分点）。

**推演混算的后果**：太原 58 + 一线 249 混算，Python 要求率得 58.0%，薪资中位得 15.5K。这个数——

- 拿去代表太原：高估 22 个百分点（真实 36.2%），薪资高估 2.6 倍（真实 6.0K）
- 拿去代表一线：薪资低估 1K（真实 16.5K）

**结论**：全国平均这个数字的问题不是"偏"，是**不属于任何地方**——它谁也代表不了。一个太原学生看着"全国 58% 要 Python、15.5K"去做准备，方向全错。所以样本小但口径对，好过样本大但口径错。

## 4. "有没有你原来以为、后来被数据推翻的判断？"（假设检验记录）

## 5. "样本才 328 条，也敢下结论？"

**承认误差**：短窗口横截面（两天采集），只能说明"这个时间窗口里的市场快照"，不能说明趋势。时间对照用的是第三方 2016 年数据集，且已声明其采集方式与局限。

**推演**：敢不敢下结论看的不是样本够不够多，是**差距够不够大**——

- Python：太原 36.2% ± 12.4 与一线 63.1% ± 6.0，两段区间不重叠 → 敢说"真的有差距"
- Excel：太原 36.2% 与一线 36.9%，区间大幅重叠 → 只说"没有城市差异"，绝不说"一线略高"

**结论**：58 条也敢出 Python 的结论，是因为差距大到晃不动；同一份数据里 Excel 的"差距"小到不敢说。报告里每个百分比后面都跟着这个判断。
