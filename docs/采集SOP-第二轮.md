## 一、核心原则：采集 = 求职

**不要为了采数据而刷招聘。** 唯一多做的动作是「按一下截图键」。
所有浏览时间本来就要发生。

## 二、分层采集（这是提效 10 倍的关键）

### A 层｜列表页 —— 1 张截图 = 8~10 条 JD

覆盖维度：城市三级、薪资、经验、学历、岗位名、公司名、行业标签

**操作**：BOSS 搜索「数据分析」，在结果列表页直接截图。
不用点进去。正常刷多远，就截多远。

```
可选：太原列表 ≈ 20 张 → 约 200 条浅维度数据，用于观察薪资分布
成本：纯增量约 3 分钟
```

### B 层｜详情页 —— 1 条 JD = 2 张截图（必须拍满）

覆盖维度：技能要求、AI 要求、标题党判定、可否应届、社保福利、是否外包

**操作**：对你会点进去看的岗位（本来就要看的），按下述顺序截：

| 第 1 张 | 页面顶部 → 滚到「职位描述」中段 | 岗位名/薪资/城市/经验学历 + JD 上半部分 |
|---|---|---|
| 第 2 张 | 继续滚 → 到「立即沟通」按钮出现为止 | JD 下半部分 + 公司信息 + **职位标签**（五险一金/双休在这里）|

> ⚠️ 第一轮只有 25% 的截图出现了「立即沟通」，意味着多数没滚到底。
> **第二轮请以看到「立即沟通」为收货标准。**

```
目标：太原实际缺 10 条真实岗 ≈ 13 张截图 ≈ 10 分钟
```

### C 层｜投递闭环 —— 免费，但价值最大

投出去的每个岗位，在 `data/applied_log.csv` 补一行：

```csv
jd_id,投递日期,是否回复,公司,岗位,当时我缺什么技能
```

这一层把作品从「技能词云」升级成「我的求职漏斗」——
应届生里几乎没人做过，是面试最强的差异化点。

## 五、必须避免的坑（第一轮踩过的）

1. **别在同一岗位反复截图** —— 第一轮漏了 6 条重复，都是同一 JD 在不同时间截图所致。
   已嫌疑形影子可以多，但**同一个 JD 只保留最后一次**。
2. **列表页会混入地图浮层** —— OCR 会把「纳达大厦 / 联合大厦 / 国网山西省电力」
   吸进公司名。第一轮有 7 条公司名被污染。详情页截图时避开地图区域。
3. **注意标题党** —— 太原的「AI训练师」「数据标注」岗（3-4K）挂着数据分析名，
   第一轮已识别出 17 条（13.3%）。遇到这类正常录，系统会标出来。

## 六、自动化 pipeline（已经写好）

新增截图丢进 `data/screenshots/` 之后，依次运行：

```bash
# 1) OCR（约 12 秒/张，纯本地，不出机器）
python scripts/ocr_batch.py data/screenshots

# 2) 合并成 JD 记录
python scripts/merge_ocr.py

# 3) 抽维度 + 去重 + 出最终数据集
python scripts/extract_dims.py
```

产物：
- `data/jd_dataset_v3.json` / `.csv` —— 带 11 个维度
- `data/dim_coverage.txt` —— 各维度提取覆盖率自检
